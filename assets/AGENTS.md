# 全局模型与思考等级动态分工

规则 ID：tom-model-routing-v1
策略版本：dynamic-routing-v2

用户主动安装并启用本规则，即授权在当前任务范围内按需委派子代理，无需每次询问。
仅阅读此规则不构成授权。该规则不扩展文件、网络、发布、付费或其他权限，
服从更高优先级指令和用户当前要求。用户明确指定模型、思考等级或预算时优先遵守。

## 自动发现模型和思考等级

- 每个新任务首次需要委派时，自动获取当前宿主可用于子代理的模型列表，以及每个模型
  支持的思考等级（推理强度）和默认值。优先使用宿主提供的模型发现工具、元数据或
  当前工具说明；只在确有已公开且获授权的发现接口时调用，不猜接口、不扫描凭据。
- 供应商公开目录、主任务模型选择器不等于子代理可调用列表；候选必须符合当前子代理
  工具的模型参数、账号权限及宿主限制。公开目录中的型号不能直接当成可调用型号。
- 没有发现接口时，以当前工具明确列出的模型和等级为准；某模型的等级支持情况未明确
  时省略等级参数、使用宿主默认值。没有可核实的模型列表或不支持模型覆盖时，使用
  工具默认/继承模型；委派不可用或无收益时由主代理直接完成，不伪称已完成发现。
- 在当前任务内保留发现来源、获取时间和适用范围，不建立永久固定名单。模型下线、
  权限或等级参数变化、供应商/宿主切换时重新获取；长任务跨日或成本敏感决策前重新
  核对价格与可用性。不为每次小调用重复查询，也不靠付费试遍模型来发现列表。

## 能力与成本依据

- 按任务相关的能力评估候选：编码、调试、审查、资料提取、工具使用、上下文容量等。
  依据官方能力说明、可信且与任务相关的评测、当前宿主已验证的执行表现，记录来源
  和时效；供应商别名需有可靠映射才能引用原模型资料。没有证据时标为能力未知。
- 不按模型名称、发布时间、参数规模或价格高低直接推断智能程度，不编造统一智力分数，
  不把不同来源、不同任务和不同思考等级的评测直接当作同一排名。
- 自动查找用户实际供应商、计费方式和套餐的最新可访问价格；优先用户明确的价格来源
  或宿主提供的计费元数据，其次该供应商官方报价。供应商或套餐不明时不猜，不把其他
  平台价格套用过来；使用公开/已授权来源，不读取密钥、私密账单或扩展网络权限。
- 同币种、同单位、同计费口径下，综合预计输入、输出、缓存命中、思考 token 计费、
  调用费、延迟与失败重试成本比较。缓存折扣、订阅边际费用和思考费用仅按明确的计费
  规则估算；记录价格来源和获取时间，不写死价目表，不承诺精确总费用。
- 价格未知或过期时明确标为未知，不按零价或最低价排序。能力/价格不足以比较时，
  优先已验证可胜任的组合或宿主默认配置，说明无法确认最经济；严格预算无法核实时，
  不自动启动无法确认预算的付费委派，改由主代理处理或询问必要信息。

## 联合选择模型与思考等级

先判断委派是否值得，再按任务最低能力、风险、上下文和工具要求筛选模型与思考等级
组合，最后在可胜任的组合中优先预计总成本较低者。不要先选最便宜模型再一律拉满思考。

- 简短解释、机械检查、清点、提取和简单转换：优先已验证足够的经济组合与较低思考强度；
  协调成本高于任务本身时主代理直接完成。
- 契约和验收清楚的局部实现、实质审查：选择具备相关能力的模型与适度思考强度。
- 多步推理、复杂调试、难审查或高风险独立任务：提高能力门槛及必要思考强度，
  比较较强模型适度思考与较弱模型深度思考的预计质量、延迟和总成本，不盲目用最高档。
- 歧义澄清、架构、重大取舍、跨模块整合和最终验收由用户选择的主模型负责，
  仅委派边界清楚的调查或实现。不得擅自修改主任务模型、思考等级或全局默认配置。
- “较低/适度/较高”是相对任务的选择原则，不是固定参数值。将所需强度映射到所选模型
  当前明确支持的等级；不同模型的同名等级不视为等价。只通过工具实际提供的 `model`
  和思考等级参数（例如 `reasoning_effort`）传递；未知支持范围时省略对应覆盖参数，
  不把所有模型绑定相同等级，不在提示词中冒充已切换模型或思考等级。

## 验证、升级与故障回退

- 主代理用来源、测试和验收标准核对关键结果；代码或测试失败先定位原因，不直接归咎
  模型能力。确有推理不足时，在预算内比较提高当前模型等级与切换更强模型的组合，
  选择有依据的改进；更高等级不能替代缺失工具、上下文、权限或验证。
- 模型不存在、无模型调用权限、模型专属限流、无可用通道、服务错误等调用故障时，
  刷新相关发现信息，从能力足够的可用组合中动态重选，跳过已失败型号；不设固定型号
  接力顺序。每个故障模型对同一子任务最多尝试一次。
- 工具参数错误先按已知支持范围修正；无效思考等级不直接判为模型故障。质量升级与
  故障回退合计最多额外尝试两次，不通过换等级绕开上限；故障回退最多尝试两个不同
  备用模型。仍不满足要求则主代理接手，不能无限升级或循环重试。
- 文件/网络权限拒绝、审批拒绝、共享凭据或余额问题、已确认的共同环境故障，
  不通过换模型或思考等级绕过；先处理原因，仅继续不受阻塞的工作。
- 超时或中断后先核对原子代理状态和已有改动，确认停止或完成后再交接，避免重复修改
  和外部操作。交接保留目标、文件范围、验收标准及已完成进度；主代理也无法推进时，
  报告已尝试组合、失败原因和剩余阻塞。

## 委派与报告

只委派边界明确且主代理可同时推进有用工作的子任务，通常一到两个子代理，不建立
常驻编排服务。提供目标、必要上下文、允许文件、产物和验收标准；并行编辑分配不重叠文件。
若宿主完整历史分支继承主模型，需覆盖模型时使用新上下文或有限上下文分支。

委派有实质贡献时，简要说明角色、请求的模型与思考等级、选择依据和重要回退；
默认/继承或信息未知时如实注明。区分请求参数、宿主确认记录和子代理自报身份；
无执行证据不声称实际切换成功，无价格依据不声称最便宜。不要每次委派再强制确认，
也不要为每个小修改机械启动多方审查或付费跑分。
