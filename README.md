# Codex 动态模型与思考等级分工

不固定型号、不固化价目表，也不把任务绑定到某个思考等级。
每个任务首次需要委派时，自动获取当前宿主支持的子代理模型与思考等级，
按任务能力要求筛选组合，再结合实际供应商成本选择；主模型负责整合与最终验收。

这是由 Codex 执行的技能和全局指令，不是独立路由网关或后台服务。
完整可安装规则见 `assets/AGENTS.md`。

## 一句话安装（推荐）

把下面这句话发给目标设备上的 Codex：

> 请根据 https://github.com/Tom9402/model-routing/blob/main/SKILL.md，安装并启用 model-routing，自动选择模型和思考等级，并验证全局规则已经启用。

无需手动下载文件。Codex 需要可访问 GitHub 和写入自身配置目录。
安装同时复制技能、写入全局规则，不需要再手动配置型号或思考等级。

## 一条命令安装

在 **Windows PowerShell 5.1 或 PowerShell 7** 中运行：

```powershell
[Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]::Tls12; & ([scriptblock]::Create((Invoke-WebRequest -UseBasicParsing https://raw.githubusercontent.com/Tom9402/model-routing/main/install.ps1).Content))
```

该命令下载并执行本仓库的安装脚本，需要信任仓库维护者。安装器下载同一提交版本的文件，
安装 skill、启用全局分工规则并验证一致性。重复运行即可更新，变更前会备份旧文件。

### “安装即生效”指什么

- 安装完成后全局规则已启用，新任务加载后自动采用，无需每次调用技能。
- 通过 Codex 安装时，当前代理应读取验证后的规则并在后续操作中采用。
- 已打开的其他任务不保证热更新，请新开任务；终端安装也请新开 Codex 任务。
- 安装不会改变你为主任务选择的模型或思考等级，不会凭空增加账号模型权限。
- 通用技能安装器如果只复制技能目录，未必启用全局规则，请使用上面的方式或运行包内安装器。

## 怎么选择

| 环节 | 自动处理 | 信息不足时 |
|---|---|---|
| 模型与等级发现 | 优先宿主发现接口、元数据及当前工具说明；获取每个模型实际支持的等级 | 使用工具明确支持范围，否则默认/继承，不猜参数 |
| 能力判断 | 参考任务相关能力说明、可靠评测和已验证表现 | 标记未知，不按型号名、价格或发布时间推断强弱 |
| 成本比较 | 获取实际供应商和套餐价格，综合输入、输出、缓存、思考费用、延迟及重试 | 不套用其他平台价格；未知不当作免费或最便宜 |
| 联合路由 | 先满足任务能力、风险和工具要求，再选预计总成本较低的模型＋思考等级 | 已验证组合或宿主默认；严格预算不明时不盲目付费委派 |
| 升级与回退 | 推理不足时比较提高等级或换模型；调用故障时动态重选 | 升级和回退合计最多额外两次，之后主代理接手 |

简单任务倾向较低思考强度，复杂调试和高风险审查提高能力门槛与必要思考强度，
但不一律选最贵模型或最高等级。不同模型同名等级不视为等价。
用户明确指定模型、等级或预算时优先遵守，不擅自修改主任务设置。

发现信息在任务内复用；模型/权限/等级支持变化或切换宿主时刷新，长任务跨日及成本敏感
决策前重新核对。公开模型目录不等于账号子代理权限，不通过付费遍历测试型号。
价格来源使用用户实际供应商，未指定供应商时不猜测；本包不绑定特定供应商。
权限拒绝、共同环境故障、凭据或余额问题不通过换模型绕过。

## 安装位置与已有配置

- skill：`$CODEX_HOME/skills/model-routing`。
- 全局规则：`$CODEX_HOME/AGENTS.md` 中的 `<!-- model-routing:start -->` 与 `<!-- model-routing:end -->` 区块。
- 未设置 `CODEX_HOME` 时使用用户主目录下的 `.codex`。
- 保留区块外指令。旧版无标记规则或损坏标记会停止安装，由 Codex 阅读完整文件、备份并确认边界后迁移。
- 不修改 `config.toml`，不安装模型，不读取凭据文件或聊天记录，不上传本机数据。
  备份只保存在本机，包含被替换文件原有内容。

包使用稳定规则 ID `tom-model-routing-v1` 识别已有安装，当前策略版本为
`dynamic-routing-v2`；规则 ID 不代表仍使用旧的固定型号策略。

## 验证与维护

让 Codex 使用 `$model-routing` 检查安装。包内 `scripts/verify.ps1` 检查文件与规则区块
一致性，不会调用收费模型。真实委派是否可用取决于当前会话工具、模型参数、账号与宿主。
应在有用的独立任务中核对请求组合、执行记录和验收结果，不以子代理自报身份作为证据。

维护者可在仓库根目录运行隔离安装回归测试：

```powershell
& ./tests/install.Tests.ps1
```

测试覆盖全新安装、重复安装、更新保留外部指令、损坏及旧版规则拒绝、篡改检测和动态策略
基本约束；不修改真实全局配置、不调用收费模型。它不能证明模型能力评估或成本估算总是最优。

自定义可修改 `assets/AGENTS.md` 后重新安装，或编辑全局专属区块。
更新会替换该区块，请先保留自己的定制。Windows 安装流程可用隔离目录测试；
macOS/Linux 尚未测试，可让 Codex 按 SKILL.md 适配。

## 移除

让 Codex 移除全局文件中的完整 model-routing 标记区块，以及对应的 `skills/model-routing`
目录，保留其他内容。不要删除整份 `AGENTS.md`，也不要盲目恢复备份覆盖后续修改。
